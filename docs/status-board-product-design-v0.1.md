Status Board 是一个桌面状态组件，让用户随时查看 Codex 的剩余额度、正在处理和等待操作的任务数量，并在任务完成或需要用户处理时听到一次提示音。它有可长期保留的展开卡片和小型悬浮图标两种形态，减少查看状态时的应用切换和菜单点击。

本文中的“已确定”来自本轮产品讨论；“原型基线”是当前选定样式的实现参数；实施建议与技术验证项不代表已实现的能力。Status Board 暂作项目名称。“插件”是产品形态描述，具体运行方式与技术栈在技术验证后选择。

## 1 产品目标与范围

### 用户场景

- 在其他应用中工作时，希望及时知道 Codex 已完成任务，或正在等自己处理。
- 想快速查看剩余额度，不再反复打开头像和多层菜单。
- 需要持续观察时，将详情卡片展开留在桌面；需要减少占用时，将其收成一个图标。
- 有多个任务并行时，只关心各类任务的数量，不需要在组件里阅读任务名称和内容。

### 首版范围

| 范围 | 内容 |
| --- | --- |
| 额度监控 | 显示剩余百分比、颜色状态和悬浮重置时间 |
| 任务监控 | 显示 processing、Waiting for operation、Done 三项统计 |
| 声音提醒 | 完成、普通待处理、异常待处理使用三种可区分的提示音，每次新事件只响一次 |
| 持续标记 | 待处理标记、完成未读标记随真实状态保留 |
| 桌面交互 | 展开、收起、保持展开、Pin 切换窗口层级、拖动和启动时恢复位置及形态 |
| 设置入口 | 顶部齿轮下拉菜单，提供静音、登录自动启动和退出 |
| 断开状态 | 保留组件和上次额度快照，明确任务状态不可用 |

首版不包含电脑 CPU、内存、电池或网络监控，不接入其他应用，不做任务内容阅读器、历史报表、额度告警、批量已读或任务执行控制。跨平台、公开发行与多账户管理也未纳入首版承诺。

### 已确定的监控范围

监控当前 Codex 桌面账户中可见的所有未归档顶层对话。多个窗口中的同一对话合并去重；子代理的工作归入父对话，不单独增加任务数量。CLI 或云端任务如果出现在上述范围内，也纳入监控，不按发起来源排除。归档对话不计入。

这是首版的产品范围；不同来源的状态和未读数据是否都能可靠读取，仍需接入验证。

### 成功标准

用户在展开卡片后能直接回答“还剩多少额度”“有多少任务在处理”“是否有事情等我处理”“有多少完成结果尚未阅读”。新完成和待处理事件能及时引起注意，同一事件不会反复响铃；组件展示与 Codex 的真实状态保持一致。

状态更新延迟、声音延迟和资源占用的量化目标，需要结合数据接入验证确定，不能用原型演示代替实测。

## 2 产品形态与窗口层级

2026-10-24 UI 调整（build 15）：展开窗口增高 48 pt，新增顶栏。左侧使用 `dinosaur/dinosaur-cute.png` 作为头像，点击头像收起；右侧依次为设置、Pin、电源键。收起后使用同一恐龙头像，点击展开。原 Codex 标识行保留；原小三角仅显示，不绑定动作或键盘焦点。所有 UI 的 Quit 入口先弹确认窗口，默认 Cancel，确认 Quit 才退出。此补充覆盖下文旧的收起入口及直接退出描述。

### 两种稳定形态

| 形态 | 内容 | 进入和退出 |
| --- | --- | --- |
| 悬浮图标 | ChatGPT 图标；存在待处理任务时，右上角显示 ! | 点击图标展开 |
| 展开卡片 | Codex 标题、额度、三项任务统计、连接和层级状态、设置齿轮、Pin 与收起按钮 | 点击标题图标区域或收起按钮收起 |

展开后点击其他位置、切换应用或操作其他窗口，卡片仍然保持展开。只有用户主动收起才改变形态；不采用点击外部自动消失的弹出菜单行为。

缩小后只表达“有任务等待操作”，不展示完成未读数量、运行数量或额度百分比。没有待处理任务时显示普通图标；仅有完成未读任务时也不增加角标。

### 默认层级和 Pin

默认使用桌面层级，普通应用窗口可以覆盖组件。开启 Pin 后，目标行为是让组件位于普通窗口和全屏应用上方；关闭 Pin 后回到桌面层级。全屏应用及不同 macOS 桌面空间中的可见性需要原生窗口验证。

2026-10-23 实机测试补充：未 Pin 时，用户点击组件应将其临时提到普通窗口前面，方便继续操作；点击其他应用后回到桌面层级。取消 Pin 时若仍在操作组件，先保留临时前置，结束操作后再降低层级。临时前置不修改 Pin 或展开状态；后台数据刷新和提醒不触发前置。

2026-10-24 窗口恢复补充：菜单栏 **Show Status Board** 在菜单关闭后展开并临时浮起面板，不改变 Pin。菜单关闭、键盘焦点短暂转移和数据刷新不结束临时前置；点击其他应用或切换应用才回到桌面层级。菜单栏增加随状态切换的 **Pin Status Board / Unpin Status Board**，与面板按钮共享保存状态；这两个菜单动作同时展开并唤出面板，取消 Pin 后保留临时前置直到下一次外部操作。面板上的 Pin 按钮仍不改变展开状态。

| 形态 | 未 Pin | 已 Pin |
| --- | --- | --- |
| 悬浮图标 | 保持小图标，可以被其他窗口覆盖 | 保持小图标，置顶显示 |
| 展开卡片 | 保持展开，可以被其他窗口覆盖 | 保持展开，置顶显示 |

Pin 与展开状态相互独立。展开或收起不应改变 Pin；Pin 表示窗口置顶，不表示锁定位置。未 Pin 时发生提醒，不自动置顶、不抢焦点、不强制展开。

### 启动与状态恢复

首次启动显示小图标，默认未 Pin，处于桌面层级。以后启动恢复上次的展开或收起状态、Pin 状态和位置。恢复界面状态不改变第 6 节的提醒规则：已有未读和待处理只恢复计数与标记，不补响。

### 拖动与位置记忆

小图标可以直接拖动；展开卡片通过顶部空白区域拖动。松手后记住位置，首版不自动吸附屏幕边缘。拖动与点击需要区分，拖动小图标不应同时触发展开；顶部按钮继续执行各自的点击操作。

### 多显示器与桌面空间

始终只有一个组件，不在多块屏幕上复制。组件留在用户放置的屏幕，不随鼠标位置或当前应用换屏；拔掉该屏幕后，回到主屏的可见位置。

切换 macOS 桌面空间时，组件继续可见，是否被普通窗口覆盖仍由 Pin 决定；已 Pin 时仍遵守全屏应用上方可见的目标。这些是已确定的产品行为，具体系统兼容性需实机验证。

## 3 展开卡片与信息层级

卡片从上到下包含四个区域。

1. 标题区：左上角 ChatGPT 图标和 Codex；右侧从左到右为设置齿轮、Pin、收起按钮，齿轮位于用户标注的 Pin 左侧位置。Codex 下方不加“1 项待处理”等副标题。
2. 额度区：每个周期一行，显示周期名称、剩余百分比和细进度条。鼠标悬浮时显示 Reset at 信息。
3. 任务区：三列汇总统计，依次为 processing、Waiting for operation、Done，不展示任务名称。
4. 底部状态区：连接状态与当前层级，分别表达是否连接、是否 Pin。

三种任务状态可以同时存在。例如 3 个任务正在处理、1 个等待操作、2 个完成未读，应同时展示三个计数，不能把整个 Codex 简化成一个“忙碌”或“完成”状态。

### 齿轮下拉菜单

点击展开卡片右上角的齿轮，弹出一个紧凑下拉菜单，依次包含以下三项。齿轮菜单是首版的设置入口。

| 菜单项 | 类型与默认值 | 行为 |
| --- | --- | --- |
| Mute Sounds | 勾选开关，默认未勾选，即声音开启 | 勾选后暂停全部提示音，任务监控、计数和视觉标记继续更新 |
| Launch at Login | 勾选开关，默认未勾选 | 开启或关闭登录后自动启动 Status Board |
| Quit | 操作项 | 退出 Status Board 并停止其监控及声音，不退出 Codex、不停止 Codex 任务 |

前两项用勾选状态表达是否启用。选择后更新状态并收起菜单。再次点击齿轮、点击菜单外或按 Escape 也会关闭菜单；关闭菜单不收起主卡片。收起卡片时同时关闭菜单。缩小形态需要先展开，才能访问齿轮。

菜单保持在屏幕可见区域，不挤动额度和任务内容。键盘可操作三项，关闭菜单后焦点返回合理位置。设置开关作为用户偏好保存，重启后恢复；首次启动默认值仅在没有已有偏好时使用。

## 4 任务状态与计数规则

### 状态定义

| 界面标签 | 含义 | 可视表现 | 离开该状态的条件 |
| --- | --- | --- | --- |
| processing | 当前正在处理的任务数 | 数字计数 | 任务停止处理，按后续真实状态更新 |
| Waiting for operation | 当前需要用户操作才能继续的任务数 | 数字计数；缩小图标右上角显示 ! | 用户处理后恢复执行，或该待处理状态结束 |
| Done | 已完成但尚未在 Codex 阅读的任务数 | 数字计数；有未读时保留小标记 | Codex 将相应完成结果标记为已读 |

Done 只统计当前已完成但未读的对话，不是历史累计完成数，也不是本次启动以来的完成总数。已经读过的完成任务不继续占据 Done 计数，不累计记录历史完成数量。

### 已确定的任务归类

| 情况 | 统计归类 | 新事件的声音 |
| --- | --- | --- |
| 正在正常执行或自动重试 | processing | 自动重试不额外响铃 |
| 等待用户回答或批准 | Waiting for operation | 普通待处理提示音一次 |
| 出错停止且需要用户重试或处理 | Waiting for operation | 异常提示音一次，与普通待处理及完成音区分 |
| 用户主动停止 | 移出三项统计 | 不响完成音，不按异常提醒 |
| 正常完成且未读 | Done | 完成提示音一次 |
| 正常完成但已经被 Codex 标记为已读 | 不计入 Done | 如果是监控期间的新完成事件，仍响完成音一次 |

异常待处理与普通待处理共用一个计数和右上角 !，通过声音区分，不新增第四项统计。异常类型以是否需要用户处理为判断依据：仍在自动重试时属于 processing，已经停住且需要用户介入时属于 Waiting for operation。

### 计数与已读同步

- 已连接且确认没有某类任务时显示 0；无法得知状态时显示 —。
- 打开组件、展开卡片、点击 Done 或听到提示音，都不直接把任务标记为已读。
- 已读以 Codex 的对应状态为依据；在 Codex 阅读后，组件同步减少 Done 计数并更新未读标记。
- 点击任务统计区域用于切换到 Codex。当前方案不包含任务列表、具体任务名称或指定对话的跳转选择器。
- 以顶层对话为计数单位，按该对话最新状态统计。每个对话同时最多贡献一个计数，不把多轮执行累计成多个任务。
- 同一对话完成未读时计入 Done；继续发起新一轮后，原 Done 计数移除，转为 processing。新一轮完成后，根据真实未读状态重新决定是否计入 Done，并对这次新完成事件提醒一次。
- 同一对话在多个窗口中出现，只计一次；子代理不额外计数；对话归档后移出监控统计。

计数按对话去重，声音按新事件去重。历史执行事件的去重信息仅用于避免重复提醒，不用于累计展示完成数量。

### 组合状态示例

以下数字仅用于说明规则。

| 情况 | 展开卡片 | 缩小图标 |
| --- | --- | --- |
| 3 个处理中，没有待处理或未读 | 3 / 0 / 0 | 普通图标 |
| 3 个处理中，1 个待处理，2 个完成未读 | 3 / 1 / 2，Done 保留未读标记 | 右上角 ! |
| 只有 2 个完成未读 | 0 / 0 / 2，Done 保留未读标记 | 普通图标 |
| 所有任务已处理且已读 | 0 / 0 / 0 | 普通图标 |
| 与 Codex 断开 | — / — / — | 灰色图标，不沿用旧的待处理角标 |

## 5 额度显示规则

额度区显示用户在 Codex 中关心的账户剩余额度，使用 n% 表达。它不等同于 API 账单、金额或单次任务的 token 消耗。

当前原型展示 5-hour remaining 和 Weekly remaining 两行。实际可用周期、数量及名称必须与接入账户的数据一致，不能把演示周期写死为所有账户的通用规则。原型中的 72% 和 18% 都是样例值。

| 项目 | 规则 |
| --- | --- |
| 数字含义 | 以整数 n% 显示剩余百分比，百分比文字与进度条使用同一份数据 |
| 颜色 | 剩余大于 40% 为绿色；大于 20% 且不超过 40% 为橙色；不超过 20% 为红色 |
| 提醒 | 不因额度偏低、变红或耗尽主动播放声音或发出额度通知 |
| 重置时间 | 平时隐藏，悬浮显示 Reset at …，包含本地日期和时间 |
| 断开后 | 保留上次成功读取的额度快照，不继续刷新；整体灰化并标注已断开 |
| 无有效数据 | 首次无缓存或没有有效额度数据时显示 —，不伪造为 0% 或 100% |

若数据源提供已使用比例，剩余比例按 100 − 已使用比例换算。缺失值和异常值应作为不可用处理，不得因缺少数据展示“额度已用完”。显示采用整数；取整方式需在实现中统一，颜色应与显示的百分比一致，避免边界上的数字与颜色相互矛盾。

颜色边界示例：41% 为绿色，40% 为橙色，21% 为橙色，20% 为红色。原型中的 18% 样例也使用红色。

产品只提供统一的连接状态，不拆成“账户额度连接”和“任务监控连接”。即使实现上可以单独读取账户额度，也遵守断开后保留快照、不继续更新的已定行为。

断开后即使超过快照中的重置时间，也继续保留原快照，不推算或自行恢复为 100%。切换账户后，不显示旧账户的额度、任务统计或更新时间；在取得可归属于新账户的有效数据前显示 —。

### 悬浮时间信息

时间信息不占用常驻卡片空间。悬浮额度行显示该周期的 Reset at …；悬浮连接状态显示 Last updated …，用于判断当前数据的新旧。两者都使用本地日期和时间，跨日也保留日期信息。

Last updated 表示当前展示数据最近一次完整成功同步的时间。断开后保留保存快照的同步时间，不因悬浮、重绘、请求失败或时间流逝而更新。没有成功同步记录时显示 Last updated —；数据源未提供重置时间时显示 Reset at —，不编造时间。

额度数值变化本身不触发声音。如果额度耗尽实际导致一个任务出错停止且需要用户处理，该任务按异常待处理规则提醒一次，不能再额外发出额度告警。

## 6 声音与持续提醒

### 事件规则

| 事件 | 声音 | 持续显示 |
| --- | --- | --- |
| 开始监控后，一个任务新完成 | 完成提示音一次 | 未读时计入 Done，并保留展开卡片中的未读标记 |
| 开始监控后，一个任务新等待用户回答或批准 | 普通待处理提示音一次 | 待处理计数；缩小状态右上角 ! |
| 开始监控后，一个任务出错停止且需要用户处理 | 异常提示音一次，与普通待处理及完成音区分 | 同样计入 Waiting for operation；缩小状态右上角 ! |
| 任务正在自动重试 | 不额外响 | 保持 processing |
| 用户主动停止任务 | 不响完成音或异常音 | 移出三项统计 |
| 同一完成或待处理事件被重复读取 | 不再响 | 按当前状态显示 |
| 待处理一直未解决 | 不周期性重复响 | 保留待处理状态 |
| 完成结果一直未读 | 不周期性重复响 | 保留 Done 计数与未读标记 |
| 用户正在使用 Codex 时出现新事件 | 未静音且未受专注模式抑制时，仍按对应事件响一次 | 与平时相同 |
| 开启 Mute Sounds 或 macOS 专注模式时发生事件 | 不响，不积压为之后补播的声音 | 计数与视觉标记继续正常更新 |
| 关闭静音或退出专注模式 | 不补响期间事件，只提醒之后的新事件 | 保留当前计数和标记 |
| 启动、唤醒或重连时恢复既有未读、待处理状态 | 不补响历史事件，包括断线期间发生的事件 | 只恢复计数和标记 |
| 用户处理后任务继续执行，之后再次需要批准或出错停止 | 按新的普通待处理或异常事件响一次 | 更新当前计数和标记 |
| 额度降低或重置 | 不响 | 更新额度显示；断开时不更新 |
| 用户在 Codex 阅读完成结果 | 不新增声音 | 更新 Done 计数与标记 |

在声音允许播放时，每个任务的完成各自提醒，不等所有任务一起结束。同一对话后续新一轮完成是新的完成事件，可以再次响一次；这不会累加历史 Done 数量。一次事件只响一次，之后由视觉状态承接提醒。

声音共三类：完成提示音、普通待处理提示音、异常提示音。采用三种固定且能区分的短音，音量跟随系统，首版不提供自定义音效。具体素材在实现时选定试听。

多个事件同时发生时依次播放短音，不重叠、不合并成一声；同一事件仍只播放一次。声音默认开启，可通过齿轮菜单中的 Mute Sounds 静音。

声音遵循 macOS 专注模式：专注模式开启时不响，保留计数和视觉标记，退出后不补响。手动静音同样不积压历史声音。若在声音排队时进入静音或专注模式，应取消尚未播放的提示，避免之后补播。专注模式的系统接入能力需在原生实现中验证。

没有系统弹窗或自动抢焦点的需求。尤其在未 Pin 且组件被其他窗口覆盖时，提醒通过声音送达，不自动抬起窗口。

### 初始快照与新事件的边界

启动、唤醒或重连时先恢复现有状态，已有未读和待处理只恢复计数和标记。断线期间发生的完成或待处理事件也不补响。恢复监控后新发生的完成或待处理事件才响。

同一任务等待批准时响一次；用户批准后任务继续执行，之后再次需要批准或出错停止，视为新的待处理事件，按对应声音再响一次。一直停在同一个等待状态不重复响。

实现需要区分初始快照、断线期间的历史事件与恢复监控后的新事件，并使用事件身份和发生时间去重。多个提示音几乎同时触发时，按事件发生顺序依次播放；不因排队增加重复事件。

仅因用户正操作 Codex，不会自动静音；手动静音及专注模式的抑制规则优先于新事件发声规则。

## 7 连接与异常展示

### 已确定的连接行为

连接状态按监控数据是否实际可用判断，不仅检查 Codex 窗口或进程是否存在。Codex 关闭，或监控数据持续读取失败时，组件进入断开状态。偶发读取失败先自动重试，不立即反复切换连接状态；具体重试及断开超时通过技术验证确定。

| 情况 | 额度区域 | 任务区域 | 整体表现 |
| --- | --- | --- | --- |
| 正常连接且取得数据 | 当前额度 | 当前三项计数 | 正常颜色；Connected |
| 首次启动，尚未取得有效数据且没有缓存 | — | — | Disconnected，不显示 Saved usage |
| 断开或 Codex 关闭，已有额度缓存 | 保留上次快照，停止更新 | 三项显示 — | 组件保留，整体灰化；Disconnected · Saved usage |
| 断开期间超过快照中的重置时间 | 继续保留原快照，不自动补满 | 三项显示 — | 保持断开；悬浮可查看快照更新时间 |
| 切换账户，新账户数据尚不可用 | —，不沿用旧账户数据 | —，不沿用旧账户统计 | 不展示旧账户快照或旧更新时间；有效数据取得后恢复正常 |
| 断开后用户继续展开或收起 | 快照不变 | 仍显示 — | 仍可切换形态和 Pin |
| 重新连接并取得有效快照 | 恢复当前额度 | 恢复当前计数与标记 | 恢复正常颜色；历史事件不补响 |

断开不等于没有任务，也不等于额度耗尽，因此不能将三个任务计数清零。灰化及连接文字共同说明当前额度是保存值。

### 数据缺失与异常规则

无有效数据与真实数值为零必须区分。首次无缓存显示 —，只有确实存在当前账户的保存快照时才使用 Saved usage。快照跨过重置时间仍作为历史数据保留，直到取得当前账户的新有效数据；不能在断开时自行生成新额度。

登录过期或接口失效持续导致数据不可用时，按已定规则进入断开状态。短暂请求失败先重试；若持续失败达到超时则灰化并冻结额度，任务显示 —，不能无限期将旧数据当作实时状态。后台健康判定、部分接口失败的检测及具体超时属于第 12 节的技术验证项。

| A45 | 手动静音或开启专注模式后有新事件 | 不发声，计数和标记更新；恢复声音后不补响期间事件 |
| A46 | 提示音排队期间进入静音或专注模式 | 尚未播放的声音取消，不在恢复声音后补播 |
| A47 | 点击 Quit | Status Board 退出并停止监控及声音，Codex 和其任务继续运行 |
| A48 | 开启或关闭 Launch at Login 后重新登录系统 | Status Board 按开关状态自动启动或保持关闭；自动启动仍遵守历史事件不补响规则 |
| A49 | 首次启动且没有有效数据或缓存 | 额度和任务显示 —，连接文案为 Disconnected，不显示 Saved usage，不伪造零值 |
| A50 | 断开期间超过已保存的重置时间 | 保留原额度快照，不自动改为 100%，保持断开状态 |
| A51 | 从一个账户切换到另一个账户 | 不显示旧账户的额度、计数和更新时间；取得新账户有效数据前显示 — |
| A52 | 悬浮额度行与连接状态，随后移开 | 分别显示 Reset at 与 Last updated 的本地日期时间；移开后不常驻 |
| A53 | 断开后等待、重绘界面或请求失败 | Last updated 保持原快照同步时间，不被这些操作刷新 |
| A54 | 没有同步时间或重置时间可用 | 对应提示使用 —，不编造时间或用当前时间代替 |

建议补充的质量验收包括：键盘可访问主要控件和 Reset at 信息；颜色以外仍有数字或文字表达状态；浅色、深色及复杂背景下文字清晰；屏幕阅读器能理解 Done 的未读含义。这些属于实现质量建议，尚未扩展为新的配置功能。

## 11 产品决策确认记录

原有 12 项问题的产品规则均已确认。刷新频率、断开超时和数据接入等依赖实测的事项转入技术验证，不把未验证的实现能力视为已交付。

| 编号 | 已确定规则 |
| --- | --- |
| P01 | 按顶层对话最新状态计数，每个对话同时最多计一次；Done 仅为当前完成未读，不累计历史轮次。 |
| P02 | 普通等待操作与出错停止且需用户介入均归入 Waiting for operation，但声音不同；自动重试保持 processing；主动停止移出统计且不响完成或异常音。 |
| P03 | 当前 Codex 桌面账户的所有可见未归档顶层对话；跨窗口去重，子代理归父对话，范围内 CLI 和云端来源也纳入。 |
| P04 | 连接按实际数据可用性判断；Codex 关闭或数据持续读取失败时断开，偶发失败先自动重试。具体超时通过技术验证确定。 |
| P05 | 周期跟随账户实际数据；剩余百分比显示整数；大于 40% 绿色，大于 20% 且不超过 40% 橙色，不超过 20% 红色；不发额度提醒。 |
| P06 | 重连只恢复计数和标记，不补响断线期间事件；恢复监控后新事件正常提醒。任务继续执行后再进入新的待处理阶段，可再响一次；同一等待状态不重复响。 |
| P07 | 首次启动为小图标、默认未 Pin；以后恢复上次展开或收起状态、Pin 和有效位置。 |
| P08 | 小图标直接拖动，卡片通过顶部空白区域拖动；松手记住位置，首版不吸附边缘。只有一个组件，不随鼠标或应用换屏；屏幕移除后回主屏可见位置，切换桌面空间时继续可见，遮挡由 Pin 决定。 |

| P10 | 时间只在悬浮时显示：额度行显示 Reset at …，连接状态显示 Last updated …，均使用本地日期和时间。刷新频率与断开超时通过技术验证后确定。 |
| P11 | 首次无有效数据或缓存时显示 —；断开跨过重置时间仍保留旧快照，不自行补满；切换账户不显示旧账户数据。 |
| P12 | 展开卡片在 Pin 左侧增加齿轮，点击下拉菜单包含 Mute Sounds、Launch at Login、Quit；声音默认开启，登录自动启动默认关闭，可自行开启。 |

## 12 技术验证与实现边界

产品需求成立不代表接入能力已经验证。当前原型模拟计数、额度、连接、Pin 和设置菜单，仅用于确认外观与交互；它没有接入真实 Codex 数据，没有实现真实提示音、系统窗口层级、应用唤起、专注模式检测或登录自动启动。原型内设置操作不改变系统设置，Quit 仅演示退出反馈。

| 验证项 | 需要得到的证据 | 对产品的影响 |
| --- | --- | --- |
| 账户额度 | 能读取与 Codex 界面一致的周期、剩余比例及重置时间 | 决定额度行、计算规则和刷新策略 |
| 刷新与连接健康 | 测量推送或轮询的延迟与成本，定义重试、部分接口失败及断开超时，验证完整成功同步时间 | 确定刷新频率、超时和 Last updated 的准确来源 |
| 实时任务状态 | 能可靠识别开始、等待用户、继续、完成、异常及主动停止，区分顶层对话与子代理，并覆盖已确定来源 | 决定三项统计及三类声音的准确性 |
| 已读同步 | 能读取 Codex 对相应完成结果的真实已读变化 | 决定 Done 是否能按已定定义实现 |
| 事件去重 | 存在稳定的任务和事件身份，能区分初始快照、新事件与重放 | 决定只响一次、不补历史音是否可靠 |
| 窗口行为 | 普通窗口、全屏、桌面空间、显示器移除与重启恢复下的实机结果 | 验证已定 Pin、单实例显示和位置恢复行为 |
| 声音与生命周期 | 三类声音排队、系统音量、静音、专注模式检测、登录启动与退出的实机结果 | 验证声音抑制不补播和三项设置行为 |
| 登录与缓存 | 明确授权方式、失效处理、账户身份、快照及时间戳的保存和隔离，覆盖首次无缓存及跨重置时间场景 | 落实已定占位、快照保留和账户切换规则 |

优先验证真实已读同步和任务事件来源，再选择整体技术栈。额度能读取不代表桌面端所有任务和未读状态都能读取；单独启动一个后台进程也不能直接假定其能镜像桌面应用状态。

如果数据源无法提供已读状态，不应私自用“点击组件即清零”替代。应把技术限制和可行替代方案带回产品确认，再调整 Done 的定义或首版范围。

实现至少需要明确任务标识、执行或事件标识、当前状态、未读信息、事件发生时间、额度周期、剩余或已用比例、重置时间和最后成功同步时间。这里列的是产品所需数据，不是对现成接口字段的承诺。

建议首版在本机处理状态和提醒，不把任务正文纳入展示或缓存。权限、支持的 macOS 最低版本、打包安装方式、资源占用目标，应在技术验证后补入实现方案。

整数取整方式、英文日期时间的具体排版、首次摆放的安全位置及三种短音素材，属于实现阶段的细节。选择时遵守已定的整数余量、本地日期时间、有效位置恢复和声音区分规则；只有技术限制会改变产品行为时，才重新确认需求。
