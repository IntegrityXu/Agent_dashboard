Status Board 是面向 Codex 桌面端用户的桌面状态组件。用户在其他应用中工作时，可以查看已验证范围内的任务状态和账户剩余额度，并通过声音及时获知任务完成或需要处理的事件。

本文以当前实现为产品基线，不将早期设计中的目标、历史实验或尚未接入的能力写成现有功能。文中的“应”“必须”表示等价实现需要满足的规则，不表示所有设备和真实场景都已完成验收。已实现但验收不完整的项目统一列于第 19 节。

阅读导航：第 1 至 3 节定义目标和统计范围；第 4 至 5 节描述界面与主流程；第 6 至 11 节定义任务、额度和提醒规则；第 12 至 15 节定义桌面交互与异常恢复；第 16 至 17 节描述数据和交付；第 18 至 20 节提供验收、质量目标与证据。

## 1 产品目标与用户

### 1.1 用户与使用场景

主要用户是使用 Codex 桌面端处理一个或多个任务、同时需要在编辑器、浏览器或其他应用中工作的个人用户。产品不设置团队管理员、成员权限或独立账户体系，使用 Codex 当前登录身份确定可展示的数据。

| 场景 | 用户问题 | 产品提供的结果 |
| --- | --- | --- |
| 在其他应用中工作 | Codex 是否仍在执行，是否需要我处理 | 展示 Processing 和 Waiting for operation 数量，必要时播放提示音 |
| 多任务并行 | 有多少任务完成但尚未查看 | 展示 Done 数量，阅读后自动移除 |
| 查看账户资源 | 当前额度还剩多少，何时重置 | 展示各可用周期的剩余百分比及重置时间 |
| 减少桌面占用 | 不想一直保留大面板 | 收起为红狐头像，保留周额度进度及待关注角标 |
| 持续观察 | 希望状态一直留在眼前 | 保持展开并按需置顶 |
| 连接或数据异常 | 数字是否可信，哪些功能仍可用 | 区分实时、缓存、不可用和部分可用，提供 Info 诊断 |

### 1.2 成功标准

1. 用户无需反复切换到 Codex，即可读懂剩余额度、处理中的任务数、待操作任务数和完成未读任务数。
2. 同一任务不因多个窗口、重复数据或子 Agent 而重复计数。
3. 新的可验证事件提供一次声音反馈；启动、恢复历史或重连不补播旧事件。
4. 不确定的数据明确显示为不可用或部分覆盖，不使用虚假的 0、完整覆盖率或更新时间。
5. 日常鼠标操作和后台更新不打断用户在其他应用中的键盘输入。
6. 账户数据不跨账户或跨用户复用；观察状态不会修改 Codex 会话。

当前产品没有使用分析或转化漏斗。上述标准通过状态对照、自动化用例和人工验收评价，不假设已存在埋点、在线指标平台或用户规模数据。

## 2 范围与边界

### 2.1 当前功能清单

| 编号 | 功能 | 当前范围 |
| --- | --- | --- |
| F01 | 启动与连接 | 发现本机 Codex，验证当前身份，获取可用状态，自动重试和手动刷新 |
| F02 | 顶层任务统计 | Processing、Waiting for operation、Done 三项聚合统计 |
| F03 | 等待识别 | 操作批准、用户输入、选项选择、权限批准及未回答的异步问题 |
| F04 | 完成未读恢复 | 启动、重连后恢复可验证的本地完成未读状态，跟随 Codex 已读变化 |
| F05 | 临时侧聊 | 纳入归属可验证的本地临时侧聊，支持实时状态及提醒 |
| F06 | Agent 活动 | 展示执行中主任务的主 Agent 与子 Agent 活动，不重复计入任务数 |
| F07 | 账户额度 | 展示有效额度周期、剩余比例、颜色和重置时间 |
| F08 | 额度缓存 | 持久保存已验证额度，在同一身份下按 Saved 方式展示 |
| F09 | 桌面面板 | 紧凑头像、展开面板、详情折叠、位置记忆、拖动和置顶 |
| F10 | 紧凑状态 | 最新未解决 Waiting 或 Done 角标、周额度外围进度 |
| F11 | 红狐休眠 | 无会话活动 30 分钟后显示睡眠头像，有活动时恢复 |
| F12 | 声音提醒 | 完成、等待、停止错误三种短音，串行播放、去重、取消及静音 |
| F13 | 设置与菜单栏 | 找回面板、置顶、刷新、打开 Codex、键盘设置、Info、退出 |
| F14 | 生命周期 | 单实例、登录启动、系统睡眠与唤醒、受控退出 |
| F15 | 可用性诊断 | 分功能状态、同步覆盖、账户范围、版本信息及本地诊断日志 |
| F16 | 分发与维护 | 可运行预览应用包、手动更新、卸载说明和随包声明 |

### 2.2 明确不包含的功能

- 普通 ChatGPT Chat 会话监控；该方向尚未接入生产产品。
- 完整覆盖所有本地、远程及云端任务；当前只能保证已验证的数据范围。
- 其他 AI 产品监控、CPU／内存／电池等电脑资源监控。
- 在面板中阅读任务标题、正文、问答内容、错误详情或完整历史。
- 新建任务、发送消息、批准操作、回答问题、停止任务、重试任务、归档或标记已读。
- 点击计数后定位具体任务、打开任务列表或筛选任务。
- 多账户并列查看、账户切换入口或独立登录页。
- 任务历史报表、完成累计统计、额度预测、额度不足通知、收费管理。
- macOS Focus 自动静音、系统通知横幅、音量滑块、自定义提醒音。
- 自动更新、正式签名与公证；跨平台版本也不属于当前基线。
- 历史桌面透镜／屏幕捕获实验、自定义头像选择器或可配置休眠时长。

### 2.3 外部依赖

用户需要安装并登录 Codex macOS 桌面端；实时任务监控依赖它运行并提供可验证数据。仅存在本地历史记录不能证明任务当前仍在执行。额度和任务来源可能各自可用，不能因为一项成功就宣称全部功能正常。

安装后的正常使用不要求用户安装开发工具。当前系统平台、菜单栏和窗口行为是产品约束；这些约束不构成对实现技术栈的限制。

## 3 术语与数据口径

| 术语 | 定义 |
| --- | --- |
| 会话／任务 | 统计单位为顶层会话的当前状态，而非消息条数、工具调用次数或执行轮数 |
| 执行轮次 | 同一会话中的一次运行；新轮次不能继承旧轮次的活动列表或事件优先级 |
| 顶层会话 | 不属于其他任务子 Agent 的会话；多窗口打开同一会话仍只算一项 |
| 临时侧聊 | 从已验证本地会话派生、满足临时侧聊身份条件的会话，可单独计入任务数 |
| 子 Agent | 归属主任务的协作 Agent，只在活动行展示 |
| Processing | 已确认正在执行，且没有优先级更高的待用户处理状态 |
| Waiting for operation | 已确认待用户输入或批准，或停止失败后需要关注 |
| Done | 当前已完成且尚未被 Codex 标记为已读的会话 |
| 已读 | 由 Codex 提供的已读状态；不能以点击本组件、经过一定时间或打开应用推定 |
| 同步覆盖 | 已确认实时状态的会话数量，与当前已纳入范围的会话总量之比 |
| Saved | 已验证身份的历史额度快照，不代表本次读取成功 |
| 完整同步时间 | 在当前纳入范围全部确认、无未归属遗留记录及功能降级时建立的同步时间；不表示整个云端账户同步完成 |

### 3.1 统计范围

主会话必须属于当前已验证账户、本机范围、未归档顶层会话。由本地清单发现的会话不因发起入口不同而直接排除，但其归属和当前状态仍须验证。CLI 发起的任务不是独立的全量支持来源。

其他账户会话、无法验证归属的遗留会话、已归档会话、远程／云端未接入会话及子 Agent 不进入顶层计数。验证成功的本地临时侧聊作为额外会话纳入。

同一会话在多个窗口出现时按会话身份去重。Processing、Waiting、Done 可同时大于 0，但同一会话最多归入其中一项；空闲、主动停止和未知状态可以不属于任何一项。

### 3.2 0 与不可用

- `0`：存在足够证据支持该统计范围内没有对应状态的任务。
- `—`：当前不足以形成可用统计或额度信息。
- 部分会话已验证时，允许显示这部分的数字；Info 必须披露覆盖范围，数字不代表全账户总数。
- 已连接但尚未取得任何可分类会话、且没有可验证恢复结果时，任务显示 `—`。
- 已确认范围为空时可以显示三项 0。
- 恢复记录能够确认最后一项 Done 已读时，Done 可变为 0，不能因为实时会话尚未加载又退回虚假的未读数。
- Processing、Waiting、Done 的和不必等于范围总量，因为总量还可能包括空闲、已读、停止及未确认会话。

## 4 信息架构与视觉规则

### 4.1 桌面形态

产品始终保留一个状态组件，包含三个可见布局状态：紧凑头像、展开且显示详情、展开但隐藏详情。展开状态与详情状态分别保存；置顶状态独立于两者。

| 布局 | 可见内容 | 主要入口 |
| --- | --- | --- |
| 紧凑头像 | 红狐头像、周额度外围进度、一个待关注角标 | 点击展开；拖动移动 |
| 展开且显示详情 | 头像、工具栏、Codex 标识、额度、三项统计、符合条件的 Agent 活动、底部状态 | 点击头像收起；箭头隐藏详情 |
| 展开但隐藏详情 | 头像、工具栏、Codex 标识、详情箭头、底部状态 | 箭头显示详情 |

展开面板自上而下为：

1. 红狐头像与工具栏，右侧按钮从左至右为 Pin、Settings、电源退出。
2. 分隔线及 Codex 标识行，右侧为详情箭头。
3. 额度区，每个有效周期一行。
4. 三列任务统计，顺序固定为 Processing、Waiting for operation、Done。
5. 有活动时显示 Agent 列表。
6. 底部左侧连接状态，右侧 `Pinned` 或 `Desktop`。

任务名称和正文不进入面板。Agent 名称属于活动标识，不等同于任务标题。

### 4.2 当前布局基线

尺寸使用逻辑点，适配不同显示缩放；等价实现应保持信息密度和操作空间。

| 项目 | 当前基线 |
| --- | --- |
| 紧凑组件 | 54 × 54；头像内容约 44 × 44；圆角方形 |
| 展开卡片宽度 | 320；含头像外延的窗口宽度为 328 |
| 展开头像 | 72 × 72；向卡片左侧外延 8，顶部外延 28 |
| 工具栏按钮 | 每项 30 × 30 的操作区域 |
| 卡片内边距 | 16 |
| 默认详情高度 | 一个额度行、无 Agent 时为 132；每增加一个额度周期增加 43 |
| 展开卡片高度 | 基础 140 加当前详情高度；隐藏详情时保留基础区域 |
| Agent 区域 | 有行时增加 21 加每行 20；最多显示 5 行高度，其余滚动 |
| 设置菜单 | 宽 180，每项高度 32 |
| 悬浮提示 | 停留约 350 毫秒显示；靠近屏幕边缘时调整位置 |
| 详情切换 | 约 260 毫秒平滑过渡，支持连续操作中反向切换；系统减少动态效果时直接切换 |

浅色和深色外观跟随系统。面板采用半透明磨砂视觉，前景文字和控件保持可读；系统开启减少透明度时使用更实的背景。断开时整体降低饱和度，紧凑头像降低不透明度。

Processing 使用蓝色语义、Waiting 使用橙色、Done 使用绿色。Done 大于 0 时，展开计数旁增加未读小点。状态还必须通过文本、符号和可访问标签表达，不能仅依赖颜色。

## 5 启动与主流程

### 5.1 首次启动

1. 保证同一用户环境中只有一个 Status Board 实例。重复启动时唤出已有实例，新实例退出。
2. 建立菜单栏入口，不显示普通 Dock 图标。
3. 没有历史偏好时，显示紧凑头像，默认未置顶、声音开启、详情偏好为展开，默认不注册登录启动。
4. 发现 Codex 并验证身份；验证前不展示历史账户缓存。
5. 独立加载任务、额度、完成／已读恢复和 Agent 数据。
6. 首次得到的数据只建立状态基线，不发历史提示音。

发现不到 Codex 时保留组件和菜单栏，Info 显示 `Codex app not found`。当前版本在启动时发现应用；用户安装或修复 Codex 后应重新启动 Status Board。

### 5.2 日常查看与回到 Codex

用户点击头像展开面板，查看统计、额度和活动，再根据需要点击任一任务计数或菜单栏 Open Codex。该操作仅打开或激活 Codex，不指定会话、不更改已读状态。

用户在 Codex 回答问题、批准操作、阅读结果或重新执行后，Status Board 根据来源更新。完成结果是否已读仍由 Codex 决定。

### 5.3 重启与恢复

恢复上次组件位置、显示器、展开状态、详情状态、置顶和静音偏好。重新验证身份后才能使用匹配缓存，随后建立实时状态并静默恢复 Done。头像空闲计时从本次启动重新开始，不恢复上一次进程的休眠计时。

## 6 任务状态与等待规则

### 6.1 分类优先级

按下表从高到低判断每个已纳入范围的会话，命中后停止继续归类。

| 顺序 | 判断条件 | 归类 |
| --- | --- | --- |
| 1 | 有已识别的待回答请求、待批准标记或未回答异步问题 | Waiting |
| 2 | 有未完成但无法可靠分类的请求，且没有命中上一条 | 未知，不能按 Processing 推断 |
| 3 | 实时运行状态仍为 active | Processing，包括仍在自动重试的任务 |
| 4 | 实时运行状态为 systemError | Waiting，属于异常待处理 |
| 5 | 当前轮次为 inProgress | Processing |
| 6 | 当前轮次为 failed | Waiting，属于异常待处理 |
| 7 | 当前轮次为 interrupted | 主动停止，不计入三项 |
| 8 | 当前轮次 completed 且未读信息已确认 | 未读计入 Done，已读不计入 |
| 9 | 空闲且已确认最新轮次覆盖 | 空闲，不计入三项 |
| 10 | 其他情况 | 未知，不臆测状态 |

协议或关键字段未通过验证时，应先将受影响数据置为不可用；上表不能代替数据有效性检查。历史记录中的 inProgress 不足以恢复 Processing，必须有当前有效状态来源。

### 6.2 状态转移

| 原状态与事件 | 新状态 | 计数变化 | 声音 |
| --- | --- | --- | --- |
| 空闲／已读完成后开始新任务 | Processing | Processing +1 | 无 |
| Processing 出现输入或批准请求 | Waiting | Processing -1，Waiting +1 | 新进入等待时一次等待音 |
| Waiting 的全部请求得到处理，恢复运行 | Processing | Waiting -1，Processing +1 | 无 |
| Processing 正常完成且未读 | Done | Processing -1，Done +1 | 满足实时事件条件时一次完成音 |
| Processing 正常完成且立即被标为已读 | 已读完成 | Processing -1，Done 不增加 | 满足实时事件条件时仍播放完成音 |
| Processing 失败但仍在自动重试 | Processing | 不变 | 无失败音 |
| 执行停止并进入失败状态 | Waiting | 按原分类移入 Waiting | 同轮次首次可验证停止失败时一次失败音 |
| Waiting 中用户重新执行 | Processing 或来源确认的后续状态 | 按新状态更新 | 不因重试动作单独响铃 |
| 执行被用户主动停止 | Stopped | 移出三项 | 无完成音或失败音 |
| Done 在 Codex 中已读 | 已读完成 | Done -1 | 无 |
| 会话归档或离开当前账户范围 | 不再跟踪 | 从所属统计移除 | 无 |
| 当前状态来源失效 | 未知／不可用 | 排除失效贡献，必要时整体显示 `—` | 取消受影响提醒 |

例：A、B 正在执行，C 等待批准，D 已完成未读，显示 `2 / 1 / 1`。A 新增三个异步问题后显示 `1 / 2 / 1`，不会把三个问题算成三个任务。D 被读后变为 `1 / 2 / 0`。

### 6.3 等待类型

识别执行批准、文件修改批准、权限批准、用户输入、选项选择和异步问题。普通等待与停止失败共用 Waiting 计数和紧凑 `!`，用不同提示音区分，不新增第四列统计。

同一任务同时存在多个未解决请求时只计 1。即使执行状态仍为 active，只要存在已确认待用户处理事项，也优先归入 Waiting。

### 6.4 异步问题

- 问题必须属于当前仍在执行的轮次。
- 仅匹配问题身份的有效、已接受回答可以清除对应问题；未接受的回复、错误匹配或单纯修改问题文案不能清除等待。
- 部分回答后，存在其他未回答问题则继续 Waiting。
- 全部问题解决且任务继续运行时回到 Processing。
- 轮次结束后不保留旧轮次异步问题造成的等待。
- 连续等待期间新增问题、问题元数据更新或分批回答，不重复播放等待音；离开等待后再次进入，可产生新的等待事件。
- 不展示或持久保存问题正文、选项和回答正文。

## 7 完成未读与恢复

Done 是当前未读完成状态，不是历史累计、今日完成或本次启动后完成总数，不设置自动到期清除。

### 7.1 恢复条件

仅在以下条件全部成立时，从持久来源恢复 Done：

1. 会话仍在当前账户本地未归档顶层范围。
2. 最新轮次具有可信的完成状态及完成时间证据。
3. 未读记录属于当前账户、当前用户和本地主机范围。
4. 会话没有更优先的实时状态，也没有因已知实时流异常而阻止历史回退。

历史完成与未读取交集，并与实时计数去重。历史 inProgress、failed、interrupted 不能据此恢复 Done；临时侧聊不参加持久恢复。

### 7.2 已读变化与冲突

实时状态优先于较旧完成记录。实时任务进入新轮次、来源中断、最新历史不完整时，不得用旧的磁盘完成结果把它重新显示为 Done。

已读变化未必伴随任务运行状态版本变化。产品需要独立核对已读状态，支持同一运行版本下清除 Done；读取过程中发生的新变化仍须再次核对，不能被较早返回的结果覆盖。

历史和实时恢复均保持静音。在组件上点击 Done、打开 Info、展开或收起，都不改变 Codex 已读状态。

## 8 临时侧聊与 Agent 活动

### 8.1 临时侧聊

只接纳来自本机、身份被验证、明确标记为临时侧聊、不是子 Agent，且派生关系最终指向当前账户有效主会话的会话。收到未知会话广播不等于取得统计授权。

已接纳侧聊参与 Processing、Waiting、Done、紧凑角标和实时提醒；主会话与侧聊可以各计 1，同一侧聊多个窗口仍只计 1。

| 情况 | 行为 |
| --- | --- |
| 初次发现或重新连接 | 验证后建立静默基线 |
| 侧聊窗口隐藏，但任务仍执行或等待输入 | 保持观察，不因为窗口不可见而丢掉活动任务 |
| 最后一个窗口离开，侧聊不再活动 | 短暂宽限后释放观察，允许临时会话被清理 |
| 所属主会话不再属于有效范围 | 移除侧聊及依赖它的侧聊 |
| 侧聊转为已持久化的主会话 | 转入主会话范围，避免重复计数和无故丢失已验证状态 |
| 实时连接重建 | 丢弃旧侧聊状态，从新连接重新发现和验证 |

当前容量边界为待验证及已接纳侧聊合计最多 64 个，候选验证期限 30 秒，窗口离开宽限约 2 秒。这些是当前处理上限，不代表产品承诺已覆盖所有侧聊。

### 8.2 Agent 列表

仅为当前处于 Processing 且未进入终止轮次的主任务显示活动行，包含一个主 Agent `root` 和已验证的子 Agent。主任务转为 Waiting、Done、停止或失去可用状态时，不继续显示其旧活动列表；进入新轮次时不能复用旧列表。

| 活动状态 | 当前显示形式 |
| --- | --- |
| running | 名称后显示 `.....` |
| done | 名称后显示 ` done` |
| stopped | 名称后显示 ` stopped` |
| waiting | 名称后显示 ` waiting` |
| failed | 名称后显示 ` failed` |
| unknown | 名称后显示 ` —` |

名称取活动路径末段，长名称中间截断，状态后缀保持可见。悬浮显示完整路径和状态。最多展示 5 行高度，超过后在列表内部滚动；多个主任务可能各有一个 root 行，通过悬浮信息补充路径。

子 Agent 完成不会独立增加 Done，也不单独播放顶层任务提示音。子 Agent 数据失败只降低活动列表可用性，不应让已验证的顶层任务计数失效。

## 9 额度与缓存

### 9.1 周期与计算

按照来源实际提供的有效周期展示，不硬编码为两个周期，也不根据返回字段的先后顺序认定哪个是周额度。当前适配范围为来源提供的主、次额度窗口，并优先采用 Codex 对应的额度分组。

| 项目 | 规则 |
| --- | --- |
| 剩余百分比 | `向下取整（100 − 已使用百分比）` |
| 输入范围 | 已使用百分比必须为有限数值且在 0 到 100 内；格式错误不能当作正常空额度 |
| 标签 | 周期为 10,080 分钟时显示 Weekly remaining；其他按整天、整小时或分钟生成标签 |
| 周期未知 | 不猜测周期名称，不把它伪装成周额度 |
| 行内容 | 周期名称、整数剩余百分比及按剩余比例填充的进度条 |
| 重置时间 | 悬浮显示 Reset at，包含日期、年份、时间及本机时区；时间未知显示 `Reset at —` |
| 空额度 | 没有有效周期时显示 Usage remaining 和 `—`，保留底条 |
| 有效空响应 | 可清除旧周期，不能把来源明确返回“没有周期”当作网络失败而永久保留旧值 |

例如已使用 59.2% 时显示剩余 40%，已使用 100% 时显示 0%。0% 是有效的耗尽状态，与 `—` 不同。

### 9.2 颜色与紧凑进度

| 剩余比例 | 颜色 |
| --- | --- |
| 大于 40% | 绿色 |
| 大于 20%，小于等于 40% | 橙色 |
| 小于等于 20% | 红色 |
| 缓存额度 | 灰色，不沿用实时阈值颜色 |

紧凑头像外围使用与圆角方形一致的进度路径，从顶部顺时针绘制，只表达周额度剩余比例。没有周额度时仅显示灰色底圈，不用其他周期替代。剩余 0% 时前景进度长度为 0。紧凑界面不显示数字百分比，访问性说明应包含周期、剩余值和是否缓存。

### 9.3 缓存规则

只在已验证身份且额度读取成功后保存额度周期、百分比、重置时间、额度读取时间和最近可用完整同步时间。任务计数和提示音队列不持久缓存。

缓存必须同时匹配服务来源、账户及用户范围。同一组织账户中的不同用户不能共用额度显示缓存。启动时验证尚未完成、身份不明或已切换为其他用户时，隐藏旧缓存。

当前额度读取失败但同身份缓存仍可用时，周期标签加 `· Saved`，进度和数字使用灰色。缓存是冻结值，不因重置时间已经过去就自动变成 100%，也不通过计时推算额度消耗。

当前缓存没有固定自动删除期限，只有最新一组保存结果，后续有效数据可覆盖。隐藏不匹配缓存不代表立即擦除磁盘；清理方式见第 16 节。

## 10 紧凑角标与头像休眠

### 10.1 角标选择

紧凑头像最多展示一个角标：橙色 `!` 表示 Waiting，绿色 `✓` 表示 Done。仅存在 Processing 时不显示角标；无未解决 Waiting 或 Done 时无角标。

1. 有可用实时事件顺序时，展示最近观察到、且仍未解决的 Waiting 或 Done 事件类型。
2. 当前最新事件解决后，回退到其余仍未解决事件中最近的一项。
3. 启动、重连、仅有恢复结果时，没有可靠的实时事件先后；按 Waiting 优先、其次 Done 建立稳定基线。
4. 只改变已读信息或重复发送快照，不能把旧事件提升为最新事件。
5. 新轮次、归档、移出范围或旧状态解除时，旧优先级失效。
6. 计数不变也可能有新事件。例如旧任务结束等待、另一任务开始等待，仍为 Waiting 1，但应更新事件先后。
7. 同一等待事件的后续元数据补充不改变优先级；已确认由一组完全不同的待处理请求替换时，可以更新视觉先后，但不因此承诺重复声音。

例：先发生 A 等待、后发生 B 完成未读，则显示 `✓`；B 已读后，如果 A 仍等待，回到 `!`。因此角标不是固定“只要有 Waiting 就永远显示 !”。

Heartbeat 任务仍按已验证状态参与数字和视觉标记，只有其声音被抑制。数据不可用时不保留已经失去可信依据的角标。

### 10.2 休眠与唤醒

连续 30 分钟未观察到会话活动时，清醒红狐切换为睡眠红狐；紧凑与展开形态共享该状态。阈值为达到 30 分钟，而不是超过后再等待一轮业务事件。

以下证据可更新活动时间：被接受的新实时会话变化、已验证会话清单活动变化，以及新鲜的正在执行任务状态。任务持续 Processing 时保持清醒。

以下行为不应制造会话活动：额度查询、相同内容的定时刷新、重复事件、初始／重连基线快照以及单纯保持 Waiting 或 Done 数量大于 0。因此尚有等待或未读任务时，头像也可能睡眠，角标继续独立表达状态。

休眠只是视觉表现，不暂停监控、通知或计时。用户拖动、展开或打开设置不应被当作 Codex 会话活动。重启应用重新计时；旧的失效 Processing 数据不能让头像一直清醒。

## 11 声音提醒

### 11.1 声音种类与触发

| 事件 | 声音 | 触发边界 |
| --- | --- | --- |
| 任务完成 | 上行双音 | 已建立连续实时观察，同一轮次从执行中转为 completed |
| 等待操作 | 重复双音 | 从非等待进入已确认待输入／批准状态，或新轮次进入等待 |
| 停止错误 | 下行双音 | 已确认由非停止失败状态进入停止失败；仍 active 自动重试时不触发 |

声音只来源于可验证的实时状态转移，不通过“计数增加了几个”反推事件。多个任务的事件按本应用观察到的到达顺序串行播放，不声称具备跨任务的全局服务端时间顺序。

### 11.2 去重和时效

- 按会话、轮次及事件身份去重；同一完成、失败或等待进入事件最多播放一次。
- 同一轮次的失败已经提醒过，不能因重复数据或重连再播一次。
- 请求记录和等待标记分别到达但描述同一次等待时，只响一次。
- 每次只播放一个声音，前一个结束后才处理下一项。
- 事件在入队和即将播放时都需检查新鲜度；观察后超过 10 秒的事件丢弃，排队不能延长有效期。
- 音效文件或播放设备失败时，该事件视为已消费，不无限重试，也不能卡住后续事件。

### 11.3 静音与取消矩阵

| 情况 | 声音行为 | 视觉状态 |
| --- | --- | --- |
| 开启 Mute Sounds | 立即停止当前声音，清空排队声音；期间事件消费后丢弃 | 继续更新 |
| 关闭 Mute Sounds | 仅响应之后的新有效事件，不补播静音期间事件 | 继续更新 |
| 应用启动／重连／历史恢复 | 只建立基线，不播放历史提醒 | 恢复可验证状态 |
| 已读变化／额度变化 | 不产生声音 | 更新相应显示 |
| 用户主动停止 | 不发完成音或失败音 | 移出统计或按后续状态更新 |
| Heartbeat 自动化 | 当前一律不发声音 | 按真实状态计数和显示角标 |
| 单个会话失效或移出范围 | 取消该会话正在播放及排队事件 | 移除其失效贡献 |
| 提醒所属连接代次更换／身份失效／账户切换 | 取消不再可信的当前及排队事件 | 重新验证后展示 |
| 系统睡眠／应用退出 | 停止播放并清队列 | 睡眠暂停监控；退出关闭组件 |
| 持续没有新鲜监控更新超过 10 秒 | 停止播放并清队列 | 按失效规则降级 |

正常音量跟随系统输出音量，产品没有独立音量调节。当前未接入 Focus 自动静音，开启系统专注模式不能被承诺为关闭本产品声音；界面应明确提示可使用 Mute Sounds。

## 12 窗口与交互

### 12.1 展开与详情

点击紧凑头像展开；点击展开头像收起。展开后点击其他应用或桌面不会自动收成头像。详情箭头只切换额度、统计和 Agent 内容，不隐藏头像、工具栏、Codex 行或底部状态。

详情隐藏后，隐藏区域不可点击，也不得继续占用访问性导航。动画期间不得让尚未稳定显示的统计区域触发操作。打开设置时若详情已隐藏，会先展开详情并保存该偏好，为设置菜单提供空间。

展开、收起和内容增减尽量保持窗口左上方锚点不变；若超出可用屏幕边界，应调整到可见区域。

### 12.2 拖动

紧凑头像、展开头像、顶部空白区域和 Codex 行非按钮区域可拖动。按钮和打开的设置菜单不能被拖动层抢占。

指针位移超过 4 个逻辑点才进入拖动；拖动结束不同时触发展开或收起。单击需在有效区域内释放。拖动过程中不阻断其他系统事件；松手后保存位置和所在显示器。

不自动吸附屏幕边缘，不因鼠标位置或当前应用切换自动换屏。多显示器下只有一个组件；保存的显示器不存在时，使用主屏并将组件放到可见区域。屏幕移除及各缩放组合仍须完成更广泛实机验收。

### 12.3 置顶与临时前置

| 状态 | 行为 |
| --- | --- |
| 未置顶且未交互 | 位于桌面层，可被普通应用覆盖 |
| 未置顶时点击／操作组件 | 临时前置，方便继续操作 |
| 用户点击其他应用或切换应用 | 结束临时前置，回到桌面层 |
| 已置顶 | 保持在普通应用窗口之上 |
| 取消置顶 | 保留本次交互的临时前置，外部操作后回到桌面层 |
| 菜单栏 Show Status Board | 展开并临时前置，不改变置顶偏好 |
| 菜单栏 Pin／Unpin | 改变置顶，同时展开和唤出面板 |
| 面板 Pin 按钮 | 只改变置顶，不改变当前展开形态 |

置顶不锁定位置。后台状态更新、提醒、菜单关闭或短暂焦点变化不能擅自更改窗口形态、位置、置顶偏好或结束临时前置。

组件已按跨桌面空间及全屏辅助窗口配置，但完整 Spaces／全屏应用组合仍属待验收范围，不能写成所有全屏应用之上无条件可见的保证。

### 12.4 焦点

鼠标点击头像、拖动、置顶、展开／收起、详情切换及普通鼠标设置操作，应保留原应用键盘输入焦点。

Keyboard Settings、Info、登录启动错误提示和退出确认需要键盘交互时，可以临时获取焦点。交互结束后返回原应用或原窗口；如果用户期间主动切换到另一个应用，不强行切回。

点击 Open Codex 或任务计数是明确的应用打开操作，可以切换到 Codex。

### 12.5 指针与帮助

可点击的任务计数区域悬浮时显示手形指针。离开、切换布局、打开覆盖菜单或关闭窗口后清理指针状态，不能让手形残留到其他区域。

额度、详情按钮、连接信息及 Agent 路径等提供悬浮说明。指针移出、点击、滚动、按键、拖动、开关菜单或开始模态交互时及时关闭帮助浮层；不修改全系统提示延迟偏好。

## 13 菜单栏与设置

### 13.1 菜单栏入口

菜单栏使用狐狸尾巴图标，顺序如下。

| 菜单项 | 行为 |
| --- | --- |
| Show Status Board | 展开并唤出面板 |
| Pin Status Board／Unpin Status Board | 根据当前状态切换文案，切换置顶并唤出 |
| Refresh | 请求重新核对身份、清单、额度、会话发现、恢复数据和连接 |
| Open Codex | 打开／激活 Codex |
| Keyboard Settings… | 展开面板，打开设置并进入键盘操作模式 |
| Info | 打开诊断信息 |
| Quit | 打开退出确认 |

Refresh 不把旧数据立即当作刷新成功，也不为恢复状态补播声音。

### 13.2 面板设置菜单

| 顺序 | 菜单项 | 状态与行为 |
| --- | --- | --- |
| 1 | Mute Sounds | 勾选表示已静音；立即取消声音并保存偏好 |
| 2 | Launch at Login | 从系统读取实际注册状态；启用／停用登录启动 |
| 3 | Info | 展示诊断弹窗 |
| 4 | Quit | 打开退出确认 |

再次点击齿轮、点击菜单外、收起面板或结束相关交互时关闭设置菜单，不因此收起主面板。选择某项后关闭菜单。前两项用勾选表达状态，不能仅靠文案变化。

Keyboard Settings 模式支持方向上／下、Tab／Shift+Tab 移动选择，Home／End 到首尾，Enter／Space 执行，Escape 关闭并结束键盘交互。普通被动鼠标模式不应截获原应用按键。

### 13.3 登录启动

默认不主动注册。开启后由操作系统管理登录启动，关闭后取消注册；重新打开设置时读取系统真实状态，不能仅相信本地开关值。

需要系统批准时显示提示并打开系统登录项设置。注册或注销失败时显示 `Could not update Launch at Login` 及错误信息，再次读取实际状态，不能虚假显示开启成功。真实注销／登录周期、不同安装路径及批准流程仍待完整验收。

### 13.4 Info

Info 是按需打开的信息弹窗，不是任务列表。包含：

- 当前连接标签。
- `Confirmed live conversations: 已确认实时数/范围总数`。
- 当前账户、本地、未归档、顶层会话范围说明；未同步会话不计入实时统计。
- 无法验证归属的遗留会话数量。
- Live tasks、Usage、History recovery、Agent list 四项状态及可读原因。
- Codex 构建号；说明兼容性按功能检查。
- Last complete sync，未知时为 `—`。

范围总数包含已验证接纳的侧聊；已恢复 Done 不等于增加已确认实时覆盖数。因此 Done 大于 0 与实时覆盖率较低可以同时成立。

Info 打开时形成当前信息视图，不承诺弹窗持续实时刷新。打开 Info 会展开主面板；关闭后遵守焦点恢复规则。

### 13.5 退出

面板电源、设置 Quit 和菜单栏 Quit 都必须进入同一确认流程。标题为 `Quit Status Board?`，提示退出后状态面板和提醒将停止。按钮为 Cancel 和 Quit，默认按钮及回车操作选择 Cancel，避免误退出。

取消后继续监控并恢复焦点。确认后停止声音、监控、定时工作及本应用拥有的辅助进程，再退出；不退出 Codex、不停止 Codex 任务、不终止其他应用的辅助进程。已打开 Info 或退出确认时，不叠加重复确认窗口。

## 14 连接与异常处理

### 14.1 可用性标签

| 显示 | 含义与呈现 |
| --- | --- |
| Connected | 当前存在有效连接数据；不自动等价于全范围覆盖 |
| Connected · Limited | 至少一项可用来源仍工作，但其他功能存在部分不可用、失败、不兼容或缓存降级 |
| Disconnected | 无有效可见实时快照，也没有可显示的额度缓存 |
| Disconnected · Saved usage | 无有效可见实时快照，但当前身份匹配的额度缓存可展示 |
| Incompatible Codex data | 关键数据格式或协议无法安全解释，需要恢复兼容性 |
| `—` | 某项数值不可用；不作 0 处理 |

某项功能仍在 checking、或只有部分会话被确认时，底部可能仍显示 Connected。是否完整覆盖必须结合 Info，不能仅根据底部标签判断。

### 14.2 分功能降级

| 故障 | 任务统计 | 额度 | 恢复／Agent／声音 |
| --- | --- | --- | --- |
| 身份无法确认 | 隐藏 | 包括旧缓存一起隐藏 | 清除不可信提示音，等待重新验证 |
| 已确认账户或用户变化 | 丢弃旧身份状态 | 不复用旧身份缓存 | 清理旧订阅与事件，新身份静默建立基线 |
| 实时任务通道断开 | 旧实时统计失效，不能保持旧运行数 | 可独立继续刷新或显示同账户 Saved | 重连后建立静默基线 |
| 额度读取失败 | 已验证任务继续更新 | 有匹配旧值则 Saved，无则 `—` | 不禁用任务或活动来源 |
| 额度格式异常 | 不受牵连 | 不覆盖最后一次有效缓存，标记降级 | 等待重试或更新适配 |
| 历史／已读恢复失败 | 可用实时状态继续 | 独立工作 | 停止采用失效的历史恢复贡献 |
| 子 Agent 来源失败 | 顶层统计保留 | 独立工作 | Agent 标记部分可用，保留仍可验证的行 |
| 单会话数据不连续、身份不符或关键字段未知 | 该会话排除并重新同步 | 独立工作 | 不用旧历史状态填补，不播放推测事件 |
| 会话范围清单短暂读取失败 | 可在有界宽限内保留先前有效范围 | 独立工作 | Info 披露异常 |
| 清单失败持续达到 30 秒或格式不兼容 | 隐藏统计、活动行和角标；格式不兼容立即生效 | 独立工作 | 取消受影响提示音 |

### 14.3 新鲜度与重试参数

下列数值是当前实现的行为基线，不是已测得的端到端延迟保证。来源响应、任务发现和系统负载仍会增加实际可见延迟。

| 项目 | 当前参数 |
| --- | --- |
| 状态向界面的常规发布 | 约每 1 秒 |
| 有效可见快照最长新鲜度 | 10 秒；失效数据不能因重绘重新变新 |
| 部分普通短暂整体失败的视觉宽限 | 最多 3 秒，且受 10 秒新鲜度约束；身份失效、不兼容和明确任务失效不适用 |
| 身份常规复核 | 约 15 秒；失败后约 5 秒重试，持续失败 30 秒重建会话 |
| 账户会话范围刷新 | 约 5 秒 |
| 额度正常刷新 | 约 60 秒；失败后约 5 秒重试 |
| 历史完成／已读常规复核 | 约 5 秒；检测到变更后约 250 毫秒合并刷新 |
| 实时 Done 已读补偿核对 | 初次约 1 秒后核对，此后约每 5 秒，避免重复并发请求 |
| 常规来源发现重试 | 约 15 秒；初始化及快照等待有独立超时 |
| 断线退避 | 1、2、4、8、15 秒，之后最多 15 秒；健康连接重置退避 |

手动 Refresh 可提前触发检查。失败重试应有上限节奏，不形成高频循环；旧请求和旧身份的迟到结果不能覆盖新状态。

### 14.4 兼容性

Codex 版本号仅用于诊断，不采用固定版本白名单拒绝所有新版本。应分别验证所需身份、范围、状态、已读、额度及 Agent 数据；允许无关新增字段，关键字段缺失、未知状态或协议语义变化则只在安全范围内继续工作。

当前使用的来源并非全账户稳定公共任务接口。兼容的新版本可以继续运行，但未来私有协议或语义变化可能需要产品更新；不能承诺永远兼容。

## 15 生命周期与可访问性

系统进入睡眠时暂停观察并停止声音；唤醒后重新连接和验证，恢复期间不补播历史提醒。组件休眠头像和系统睡眠是两件独立的事。

持久保存位置、显示器、展开、详情、置顶和静音。设置菜单打开状态、临时前置、键盘焦点、声音队列、运行计数和头像空闲计时只属于当前进程，不跨启动恢复。登录启动状态由系统实际注册结果决定。

界面提供按钮名称、设置开关 On／Off、展开状态、任务计数含义、额度百分比与重置时间、Agent 状态及紧凑角标说明。额度可进入焦点导航，头像提供展开／收起动作；详情隐藏时从访问性树中隐藏对应内容。

当前界面文案为英文，没有语言切换入口。深浅外观、减少透明度和减少动态效果跟随系统；完整 VoiceOver、键盘路径、多显示器和全屏组合仍待人工验收。

## 16 数据与隐私要求

### 16.1 业务数据契约

下表定义实现必须表达的信息含义，不要求使用指定类名、数据库表或通信协议。

| 对象 | 必需信息 | 生命周期 |
| --- | --- | --- |
| 已验证身份 | 服务来源、账户、用户范围及匹配指纹 | 原始认证材料仅在内存核对；指纹可用于额度缓存 |
| 会话范围 | 会话身份、本地性、账户归属、是否归档／子 Agent／侧聊 | 会话级内存状态，随来源刷新 |
| 当前观察 | 会话、当前轮次、运行状态、待处理请求身份、未读状态、有效性与新鲜度 | 内存；不能把旧观察持久化为实时任务 |
| 完成恢复 | 当前范围内最新轮次完成证据与同身份本地未读集合 | 从只读来源恢复，不修改来源 |
| Agent 活动 | 所属主任务及轮次、Agent 身份、路径、活动状态 | 随主任务活动存在，结束清理 |
| 额度窗口 | 周期身份、周期时长／名称、剩余值、可选重置时间、读取时间 | 可按已验证身份保存 |
| 通知事件 | 会话、轮次、类型、唯一发生身份、观察时间、所属连接代次 | 短时内存；消费、过期或失效即移除 |
| 功能状态 | 功能名称、available／checking／partial／unavailable／incompatible／saved、可读说明 | 当前状态 |
| 用户偏好 | 位置、显示器、展开、详情、置顶、静音 | 本地保存 |

### 16.2 只读与最小化

观察账户和任务时不提交提示词、不批准操作、不更改会话内容、不标记已读。仅保留形成状态、归属、计数及活动所需的元数据，不将任务正文、工具参数、命令、错误原文作为展示或持久内容。

认证材料可能在身份验证时经过内存，状态传输中也可能包含被跳过的正文字节。因此产品承诺是“不展示或持久保存会话正文与原始凭据”，不能扩大为“任何正文或凭据都不会经过进程”。

当前没有向维护者服务器上传数据、广告、使用分析或自动崩溃上报功能；依赖的 Codex 组件仍可能联网，因此不宣称完全离线。正常运行不要求屏幕录制或辅助功能控制权限。

### 16.3 保存与清理

| 数据 | 当前保存位置／规则 | 清理方式 |
| --- | --- | --- |
| 偏好与额度缓存 | 本机偏好域 `local.statusboard.app`；无固定自动删除期限 | 应用退出后清除此偏好域，位置和静音等一起重置 |
| 普通诊断日志 | `~/Library/Logs/Status Board/diagnostics.jsonl`，另有 `.1` 轮转文件，各上限 1 MiB | 用户可手动删除这两个文件 |
| 登录启动 | 操作系统登录项 | 应用设置或系统设置中关闭 |
| 显式开启的调试输出 | 启用者指定位置；不沿用普通日志轮转 | 启用者自行保管和删除 |

诊断仅记录时间、构建号、固定阶段及事件、安全错误码、重试次数、恢复耗时和必要环境版本等。普通日志不得包含原始令牌、账户／会话 ID、正文或原始服务错误文本；日志写入失败不得中断监控。

卸载应用不自动删除偏好、额度缓存或日志。清理 Status Board 不应要求删除 Codex 的数据目录、认证文件或会话数据库。账户指纹不是匿名保证，隐藏缓存也不是安全擦除。

## 17 安装与发布要求

### 17.1 当前交付形式

提供适用于 macOS 15.0 及以上、包含 Intel 和 Apple Silicon 两种架构的可运行 ZIP。用户解压后将 Status Board.app 放入 Applications，再启动。运行不依赖源码目录、开发服务器、开发工具或本地未分发素材。

当前预览包使用本地 ad-hoc 签名，没有 Developer ID 正式签名和 Apple 公证。文档应如实说明首次打开可能受系统安全策略限制，不能将文件校验值描述为安全认证。

### 17.2 发布内容

- 使用当前红狐应用图标、清醒／睡眠头像和狐狸尾巴菜单栏图标，包含三种提示音。
- 附带版本信息、最低系统要求、预览限制、可运行包和 SHA-256 校验文件。
- 应用包内附带许可证、免责声明、隐私说明、第三方素材说明及安全报告说明。
- 发布前检查包完整性、架构、资源存在性和签名；从解压后的交付物验证，不能只验证构建目录中的应用。
- 宣传截图使用合成数据，避免暴露用户真实额度或任务信息。

### 17.3 更新与卸载

当前手动更新：退出旧版本，下载并替换应用后重新打开，保存的偏好和匹配额度缓存继续按规则处理。没有自动检查或自动安装更新。

卸载前关闭已开启的登录启动，退出应用，再移除应用包。需要彻底清理本产品本机数据时，按第 16 节处理；不能以“移除应用”宣称所有记录已自动清除。

### 17.4 维护辅助入口

当前支持显式启动声音试听模式 `--preview-sounds`：顺序试听三种内置声音，不启动任务监控、不修改偏好，但会忽略已保存的静音开关。该模式属于主动试听，不能与正常运行的静音承诺混淆。

显式诊断模式可向指定的现有文件追加聚合数据，包括计数、额度、覆盖率、Agent 数量和功能状态；预览／渲染模式可生成界面图片。它们不属于普通启动自动上传的遥测，不使用普通日志的自动轮转规则，产物由启用者保管。

| A40 | P1 | 展开面板后点击其他应用 | 面板保持展开；未置顶临时前置结束 |
| A41 | P1 | 开启／取消 Pin，展开／收起，使用菜单栏找回 | 置顶与形态独立；Show 不改变 Pin；菜单栏 Pin／Unpin 会唤出 |
| A42 | P1 | 隐藏详情后尝试点击原统计区域，再打开设置 | 隐藏内容不可操作；打开设置自动恢复详情空间 |
| A43 | P1 | 点击任一任务数字 | 仅打开 Codex，不指定会话、不标记已读 |
| A44 | P1 | Agent 行超过 5 行并有长名称 | 列表内部滚动，名称截断不覆盖状态，悬浮可查看完整路径 |
| A45 | P1 | 退出再启动，或移除原显示器 | 恢复偏好；原显示器不存在时窗口回到可见区域 |
| A46 | P1 | 用 Keyboard Settings 完成导航，再按 Escape | 键盘选项可操作，关闭后合理恢复焦点；主动换应用则不强行切回 |
| A47 | P1 | 开启登录启动遇到待批准或失败 | 显示系统实际状态；需要批准时引导系统设置，失败不得显示成功 |
| A48 | P1 | 点击任一退出入口并直接按回车 | 默认 Cancel；明确选 Quit 才关闭组件与自有辅助进程 |
| A49 | P0 | 额度失败、Agent 失败、历史失败分别注入 | 各功能独立降级，已验证的其他功能继续可用，Info 可解释原因 |
| A50 | P0 | 无新鲜状态超过 10 秒，或清单连续失败达到 30 秒 | 不继续展示失效任务为当前状态；身份失效与不兼容不等待宽限 |

| A52 | P1 | 切换深浅外观、减少透明度和减少动态效果 | 内容可读，状态不只靠颜色，详情动画遵守系统偏好 |
| A53 | P0 | 普通运行后检查保存内容及日志 | 无正文、原始令牌或账户／会话 ID 出现在普通日志；日志轮转有界 |
| A54 | P1 | 解压交付包，在无开发环境的稳定安装路径启动 | 资源完整、无源码运行依赖；版本、架构、签名和校验值与发布说明一致 |

## 19 质量目标与当前验证状态

### 19.1 非功能验收目标

下列目标沿用已有工程验收基线，仅规定可观察结果，不限定实现方案。当前没有完成正式延迟、资源占用和长期稳定性验收，不能将这些数值写为已经达到。

| 指标 | 验收目标 | 测量方式 |
| --- | --- | --- |
| 本地交互响应 | p95 不超过 100 毫秒 | 正式构建上记录至少 50 次展开、收起、置顶及菜单操作的初始响应；不把 260 毫秒设计动画总时长当作初始响应延迟 |
| 任务及已读传播 | p95 不超过 3 秒，最大不超过 5 秒 | 至少 20 次已验证来源的真实转移，记录来源时间与组件可见时间；来源未覆盖的任务须单独说明 |
| 声音启动 | 空队列时，有效归一事件接收后 1 秒内开始 | 与来源传播延迟、主动排队时间分别测量 |
| 额度刷新 | 正常连接下，上游可观察变化后 65 秒内更新 | 实际变化与可控模拟分开记录 |
| 重复行为 | 确定性重放及真实检查中，重复计数与重复声音均为 0 | 重复事件、多窗口、重连、恢复和子 Agent 用例 |
| 空闲 CPU | 预热后 10 分钟平均低于单核 1% | 计入本产品造成的辅助进程开销，排除无关 Codex 工作负载 |
| 内存 | 组件驻留内存低于 100 MiB；自有辅助进程增量低于 150 MiB | 在明确主机及任务规模下预热后测量 |
| 稳定性 | 2 小时无崩溃、无无限队列增长，预热后内存漂移低于 20 MiB | 覆盖正常使用、突发事件、断线、唤醒及静音切换；Focus 不在当前实现验收中 |

可靠性还必须满足：未知数据不伪装有效值，迟到结果不覆盖新身份或新轮次，单个来源故障不拖垮其他来源，诊断失败不影响业务，退出不残留本应用自有工作。

### 19.2 已记录证据

build 39 的验证记录包含 163 项核心测试、185 项原生窗口断言、通用 Release 构建、ZIP 完整性及解压后签名检查。头像时间规则具有确定性测试及合成渲染证据；异步问题曾有真实等待计数和可听声音的用户确认。

这些记录证明对应场景，不等于本文 A01 至 A54 全部完成最终交付验收，也不是本次文档工作重新运行产生的结果。实际运行与原生界面验证主要来自 Intel macOS 15.8.1；通用二进制构建不能替代 Apple Silicon 实机验证。

### 19.3 待完成的验收与决策

| 项目 | 当前结论 | 完成条件 |
| --- | --- | --- |

| 真实任务转移矩阵 | 部分验证 | 补齐真实批准、失败、重试、短等待、多任务突发及侧聊转移 |
| 实际账户切换与恢复 | 部分验证 | 真实切换账户／用户、Codex 退出重开、故障及睡眠唤醒对照 |
| 登录启动 | 注册能力已实现，完整周期待验收 | 开关、系统批准、注销登录及稳定安装路径验证 |
